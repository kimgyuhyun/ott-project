# 부하 테스트 실측 결과

시나리오·실행법은 [README.md](README.md) 참고. 이 문서는 **실제로 돌린 결과**만 기록한다.

## 2026-07-27

| 항목 | 값 |
|---|---|
| 대상 커밋 | `68d0023` (백엔드 이미지 `ghcr.io/kimgyuhyun/ott-backend:68d0023...`) |
| 구성 | 백엔드 2인스턴스(ott-app, ott-app-2) + Postgres + Redis, 단일 호스트 |
| 호스트 | 논리코어 12. Kafka·RabbitMQ·Prometheus·Grafana·Loki 가 같이 상주 |
| 부하 | ramping-vus 0→500 (2분) → 500 유지 (5분) → 0 (30초), 총 7분 34초 |
| 생성기 | k6, 같은 호스트에서 실행 |

### 결과 1: nginx 경유 — 측정 실패

목표 부하를 만들지 못했다. **서버 문제가 아니라 레이트 리밋에 막힌 것**이다.

| 지표 | 값 |
|---|---|
| 실패율 | **72.70%** (38,058 / 52,349) |
| 로그인 실패율 | 77.27% (1,700 / 2,200) |
| 처리량 | 115.2 RPS (시도 기준) |

실패 응답은 전부 nginx 가 백엔드에 보내지 않고 돌려준 것이다. `docker logs ott-nginx` 의
`limiting requests` 기록이 38,059 건으로 k6 가 센 실패 38,058 건과 일치했다.

원인은 `limit_req` 가 `$binary_remote_addr` 기준이라 VU 500 명이 IP 한 개의 버킷(general 30 r/s)을
공유한 것. 실사용자 500 명이면 IP 가 흩어져 발생하지 않는다. 자세한 내용은 README 의 레이트 리밋 절.

이 구간의 지연 수치(p95 14ms 등)는 **리밋을 통과한 26% 에 대한 값이라 성능 지표로 쓸 수 없다.**

### 결과 2: 백엔드 직결 — SLO 통과

nginx 를 건너뛰고 두 인스턴스를 직접 때렸다(`BACKENDS`). 리밋을 만나지 않으므로 목표 부하가 실제로 걸렸다.

| 지표 | SLO | 실측 | 판정 |
|---|---|---|---|
| 진행률 저장 p95 | < 500ms | **10.56ms** | 통과 |
| 목록 조회 p95 | < 300ms | **6.48ms** | 통과 |
| 상세 조회 p95 | < 300ms | **7.65ms** | 통과 |
| 스트림URL p95 | < 500ms | **6.83ms** | 통과 |
| 로그인 p95 | < 1000ms | **81.04ms** | 통과 |
| 에러율 | < 0.1% | **0.00%** (0 / 52,823) | 통과 |
| 로그인 실패율 | < 1% | **0.00%** (0 / 500) | 통과 |

| 그 외 | 값 |
|---|---|
| 총 요청 | 52,823 (116.3 RPS) |
| 이터레이션 | 37,657 완주, 중단 0 |
| 전체 응답시간 | avg 7.5ms / med 6.81ms / p90 9.22ms / p95 10.46ms / max 138.29ms |
| 전송량 | 수신 108MB / 송신 14MB |
| k6 CPU | 평균 0.4% / 최대 0.9% (12코어 기준) |
| 호스트 CPU | 평균 24.9% / 최대 71.3% |

k6 CPU 가 1% 미만이므로 **생성기 병목이 아니다.** 호스트 CPU 에 여유가 있었고 이터레이션이
하나도 밀리지 않았다(iteration_duration med 5.00s = 설계값 그대로). 즉 목표 부하 500 명에서
백엔드는 한계 근처에도 가지 않았다.

### 결과 3: 레이트 리밋 동작 확인

`limit_req_status 429` 적용(`5f559b5`) 후, nginx 로 10초간 200 RPS 를 몰아쳤다.

| 지표 | 값 |
|---|---|
| 통과 | 337 건 (33.7 r/s — 설정 30 r/s + burst 와 일치) |
| 차단 | 1,663 건 **전부 429** |
| 503 | 0 건 |
| 폭주 직후 정상 요청 | 5 / 5 모두 200 (즉시 복구) |

## 한계

- **절대 RPS 는 이 호스트에서만 유효하다.** 다른 사양에 그대로 적용할 수 없다.
- 결과 2 는 측정 경로에서 **nginx 와 TLS 가 빠져 있다.** 엣지 구간의 비용은 포함되지 않았다.
- 생성기가 같은 호스트에서 돌았다. CPU 기록으로 병목이 아님은 확인했으나 이상적인 구성은 아니다.
- **포화점(knee)은 아직 측정하지 않았다.** 목표 부하 통과만 확인했고 한계가 어디인지는 모른다.
