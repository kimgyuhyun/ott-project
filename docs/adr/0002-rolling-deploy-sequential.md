# 0002. 무중단 배포는 인스턴스 증설이 아니라 순차 교체로 한다

- 상태: 채택
- 관련: `docs/deployment.md`, `docs/messaging.md`

## 배경

배포 중 요청이 끊기는 것을 없애려고 백엔드를 2인스턴스(`docker-compose.ha.yml`)로 늘렸다.
**인스턴스를 늘리는 것만으로는 무중단이 되지 않았다.**

두 인스턴스를 동시에 재생성하면 교체 구간이 그대로 노출된다.

| 측정 | 결과 |
|---|---|
| 동시 재기동 | 197요청 중 **164건 502** |
| 순차 교체 + `proxy_next_upstream` | 374요청 중 **0건 실패** |

## 결정

`deploy-rolling.ps1` 로 인스턴스를 **한 번에 하나씩** 교체한다. nginx `proxy_next_upstream` 을
함께 적용해 교체 중인 인스턴스로 간 요청이 남은 인스턴스로 넘어가게 한다. 둘 중 하나만으로는
성립하지 않는다.

ha 오버레이를 맨손 `up` 으로 올리면 동시 재생성이 되므로, 배포 경로를 스크립트 하나로 고정한다.

## 대안

| 대안 | 판단 |
|---|---|
| 인스턴스 수만 더 늘리기 | **기각.** 동시 재생성이면 개수와 무관하게 교체 구간이 노출된다. 실측이 그 근거다 |
| 블루/그린 배포 | 검토하지 않음. 단일 호스트라 스택을 통째로 이중화할 여유가 없었다 |
| 로드밸런서 헬스체크 기반 드레이닝 | 검토하지 않음 |

## 결과

- 배포 시간이 인스턴스 수만큼 늘어난다
- **롤링 중에는 컬럼 DROP/RENAME 마이그레이션이 구버전 인스턴스를 깨뜨린다.** expand/contract
  패턴을 써야 한다. 테이블 추가·nullable 컬럼·DEFAULT 있는 NOT NULL 은 안전하다
- 단일 인스턴스로 되돌리는 `deploy.ps1` 은 `ott-app-2` 가 떠 있으면 실행을 거부한다 (실수로
  HA 를 해체하는 것을 막는 가드)
- **2인스턴스가 되면서 `@Scheduled` 스케줄러가 양쪽에서 도는 문제가 따라왔다.**
  무중단 배포의 부수 비용이다. ShedLock(Redis 분산락)으로 해결했고 재측정으로 확인했다
  (이벤트 50건 → 발행 100건, 적용 후 50건). 상세는 `docs/messaging.md` "다중 인스턴스와 중복 발행"
