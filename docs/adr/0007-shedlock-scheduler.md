# 0007. 다중 인스턴스 스케줄러는 ShedLock 분산락으로 하나만 돌린다

- 상태: 채택
- 관련: `docs/messaging.md`, [0002](0002-rolling-deploy-sequential.md), [0003](0003-sync-provisioning-async-side-effects.md)

## 배경

무중단 배포를 위해 백엔드를 2인스턴스로 늘리자([0002](0002-rolling-deploy-sequential.md))
`@Scheduled` 스케줄러가 양쪽에서 돌기 시작했다.

아웃박스 발행기(`OutboxPublisher`)는 미발행 행을 집어 Kafka 로 실어보낸다. 인스턴스가 2개면
**양쪽이 같은 행을 각자 집어 같은 이벤트를 두 번 발행한다.**

| 재현 | 결과 |
|---|---|
| `docker-compose.multi.yml` 로 2인스턴스, 이벤트 50건 투입 | **100건 발행** |

**이 문제는 인스턴스를 늘리기 전까지 드러나지 않는다.** 무중단 배포를 택하는 순간 같이 따라오는
비용이고, 단일 인스턴스로 개발·테스트하면 끝까지 보이지 않는다.

## 결정

ShedLock(Redis 프로바이더)으로 **매 실행마다 한 인스턴스에서만** 돌게 한다 (`ShedLockConfig`).
락은 Redis 에 `job-lock:ott:<name>` 키로 잡힌다.

**스케줄러 5개 전부**에 적용한다 — 아웃박스 발행, 결제 대사, 정기결제, 멤버십 알림, 통계 스냅샷.
중복 발행이 실제로 관측된 건 아웃박스뿐이지만 나머지도 같은 조건에 놓여 있다.

ShedLock 은 "항상 같은 인스턴스"가 아니라 "매 실행마다 하나만"을 보장한다. 한쪽을 내려도 다른
쪽이 이어받는다.

## 대안

| 대안 | 판단 |
|---|---|
| 스케줄러를 한 인스턴스에서만 켜기 (프로파일 분리) | **기각.** 롤링 배포는 모든 인스턴스를 한 번씩 내린다. 스케줄러를 가진 쪽이 교체되는 구간에 스케줄러가 아예 멈춘다 |
| 아웃박스 행을 DB 락(`SELECT ... FOR UPDATE`)으로 선점 | **기각.** 아웃박스에만 통한다. 나머지 4개 스케줄러는 특정 행을 잡는 구조가 아니라 커버되지 않는다 |
| Quartz 클러스터 모드 | **검토하지 않음** |

## 결과

- 재측정: 같은 방법으로 이벤트 50건 → **발행 50건, 중복 0**
- **`lockAtMostFor` 는 실제 실행시간보다 넉넉해야 한다.** 초과하면 락이 먼저 풀려 중복 실행이
  된다. 그래서 정기결제는 `PT30M`(외부 결제 API 를 건건이 호출), 나머지는 `PT9~10M` 이다
- `lockAtMostFor` 는 락을 쥔 인스턴스가 죽었을 때 락이 영구히 남지 않게 하는 상한이고,
  `lockAtLeastFor` 는 실행이 너무 빨리 끝나 다른 인스턴스가 곧바로 이어 도는 것을 막는 하한이다
- Redis 가 스케줄링의 단일 장애점이 된다. Redis 가 죽으면 락을 못 잡는다
- 운영 로그 레벨이 INFO 라 ShedLock DEBUG 로그는 보이지 않는다. 동작 확인은 Redis 락 키로 한다
- **컨슈머 멱등 처리와 층이 다르다.** 멱등 컨슈머는 "중복이 와도 결과가 같게"
  ([0003](0003-sync-provisioning-async-side-effects.md)), ShedLock 은 "애초에 중복을 만들지
  않게" 다룬다. 하나가 다른 하나를 대체하지 않는다
