# 0008. HLS 서명은 엣지에서 검증하고 하위 URI 에 캐스케이드로 붙인다

- 상태: 채택
- 관련: `docs/streaming.md`, `docs/security.md`

## 배경

영상은 오브젝트 스토리지(R2)에 올린 다화질 HLS 다. **원본 스토리지를 공개해 두면 URL 하나가
새는 순간 누구나 무제한으로 받아간다.** 멤버십으로 재생 권한을 나눠도 의미가 없어진다.

문제는 HLS 의 구조다. 재생목록 하나가 아니라 **세그먼트가 수백 개**고, ABR 이라 어떤 화질을
고를지도 재생 중에 바뀐다. "무엇에 서명할 것인가"가 그대로 설계 문제가 됐다.

## 결정

스토리지 공개 접근을 끄고, 서명된 요청만 통과하는 엣지를 유일한 경로로 둔다. 2단 구조다.

1. **발급 게이트** — `PlaybackAuthService.canStream` 이 로그인·공개여부·화수·멤버십을 보고
   서명 URL 을 줄지 결정한다. 여기서 막히면 서명 자체가 안 나온다
2. **엣지 검증** — Cloudflare Worker(`edge/hls-worker`)가 만료와 서명을 검증한다. 백엔드가
   아니라 엣지에서 거르므로 **위조·만료 요청은 오리진에 닿지도 않는다**

백엔드가 서명하는 건 진입점 `master.m3u8` **하나뿐**이다. 응답이 재생목록이면 Worker 가 본문의
하위 URI(자식 재생목록·세그먼트)에 **직접 서명을 붙여 되쓴다**(캐스케이드).

## 대안

| 대안 | 판단 |
|---|---|
| 세그먼트마다 백엔드에 서명 요청 | **기각.** 재생 중 수백 회 왕복. 백엔드가 재생 경로에 상주하게 된다 |
| 서명 쿠키 발급 | **기각.** 스토리지·엣지가 쿠키를 신뢰해야 하고 경로 깊이 규칙이 따라붙는다 |
| 경로 프리픽스 단위 서명 | **기각.** 한 번 새면 그 아래가 전부 열린다. 만료 단위가 거칠어진다 |

캐스케이드는 백엔드 왕복을 **재생당 1회**로 줄이면서 세그먼트 단위 서명을 유지한다.

## 결과

- **서명 로직이 백엔드와 Worker 두 곳에 존재한다.** 서명 포맷이나 시크릿을 바꾸면 반드시
  양쪽을 같이 배포해야 한다. 이 결정의 가장 큰 운영 비용이다
- `SECURE_LINK_SECRET` 이 백엔드 `.env.enc` 와 Worker secret 양쪽에 같은 값으로 존재한다
- **TTL 의 의미가 바뀐다.** 캐스케이드는 master 의 만료값을 하위 세그먼트까지 물려주므로,
  TTL 은 "URL 이 유효한 시간"이 아니라 **한 번 시작한 재생 세션이 살아 있어야 하는 시간**이다.
  짧게 잡으면 일시정지·탐색 중에 세션 한복판에서 403 이 난다
- 화질별 티어링은 두지 않는다. 통과한 사용자는 동일한 ABR 사다리를 받는다 — 서버가 화질을
  잘라내면 ABR 이 망가진다. 접근 제어는 허용/차단만 한다
- **스토리지 공개 접근이 다시 켜지면 이 설계 전체가 무력화된다.** 우회 경로가 생긴다
- 만료와 위조가 같은 403 으로 나온다. 장애 대응 시 시각을 함께 봐야 구분된다
